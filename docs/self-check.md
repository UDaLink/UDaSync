# 自检与验收

## 1. 自动化测试

### 单元测试（`npm test`，20 项）

| 文件 | 覆盖点 |
| --- | --- |
| `tests/model.test.ts` | UUID 分配、内容指纹、删除→墓碑、根节点按位置识别（兼容非 1/2/3 的 profile）、备份子树排除 |
| `tests/merge.test.ts` | 后写赢、存活 vs 墓碑、父删级联、同名文件夹去重、兄弟重排序、墓碑 TTL |
| `tests/plan.test.ts` | 差异统计、移动/排序判定、创建深度排序、删除顺序、本机清空保护 |
| `tests/webdav.test.ts` | PROPFIND 解析、路径拼接、gzip 快照编解码、错误包装 |

### 端到端（`npm run test:e2e`，真实坚果云 + 双 Chrome 实例）

启动两个独立 profile（A、B），加载同一份 `dist/`，通过 CDP 直接调用 `chrome.bookmarks` 与扩展消息：

| # | 场景 | 断言 |
| --- | --- | --- |
| 1 | A 首次绑定 | 绑定成功，不进入预览，本机树上传 |
| 2 | A 首次推送统计 | 状态 `ok`，计数结构完整 |
| 3 | A 生成 `[本机备份]` | 书签栏出现备份文件夹 |
| 4 | B 首次绑定 | 云端已有数据 → 返回合并预览 |
| 5 | B 确认合并 | 写入成功 |
| 6 | B 收到 A 的 GitHub | 跨设备新增可见 |
| 7 | B 收到 A 的 Figma | 同上 |
| 8 | B 保留本地少数派 | 合并不丢本地数据 |
| 9 | 同名文件夹去重 | 「工作」只剩一个（排除备份子树） |
| 10 | A 手动同步 | 成功拉取 B 的改动 |
| 11 | A 收到少数派 | 反向新增可见 |
| 12 | A 收到 B站 | 同上 |
| 13 | B 删除传播 | A 跟随删除 B站 |
| 14 | 冲突后写赢 | B 更晚的改名 `GitHub-B` 生效 |
| 15 | popup 渲染 | 状态与按钮正常 |
| 16 | 设备列表 | 两台设备均登记 |

回收站、云端备份、预览不写盘、备份子树隔离由单元测试与手工验收覆盖（见 §2）。

E2E 运行前会清理 `JGY_DIR` 下的测试快照（坚果云不允许删目录，逐文件 DELETE）。凭证只从环境变量读取，不落盘。

## 2. 手工验收清单

安装 `dist/` 后按顺序检查：

- [ ] 设置页能保存并测试连接，错误账号返回 401 文案
- [ ] 首次同步出现预览，取消后本地书签不变
- [ ] 确认后书签栏出现 `[本机备份] 设备名 时间`
- [ ] 新增书签 5 秒内触发同步，另一端 10 分钟内出现
- [ ] 改名、移动、删除分别能在另一端生效
- [ ] 同名文件夹不会重复
- [ ] 关闭再打开浏览器，启动同步正常
- [ ] 暂停后自动同步停止，手动同步仍可用
- [ ] 断网时状态为错误，恢复后下一次同步自动收敛
- [ ] 回收站能恢复误删书签
- [ ] 备份页能回滚到历史快照
- [ ] 移除旧设备后不再读取其快照

## 3. 构建产物检查

`npm run build` 结束会执行 `scripts/verify-dist.mjs`，校验：

- `manifest.json` 存在且 `manifest_version === 3`
- `background.js`、`popup.html`、`options.html`、`assets/*`、`icons/icon{16,32,48,128}.png` 齐全
- 清单引用的路径全部存在

## 4. 已知限制

- 坚果云免费版 30 分钟 600 请求，扩展内置 450 次预算并自动退避
- 不支持递归删除目录（403），清理逐文件执行
- 快照为整棵树的 gzip JSON，书签规模 > 5 万时建议增大轮询间隔
- 暂不支持 OneDrive；`StorageAdapter` 已预留
- 浏览器品牌版无法用命令行加载扩展，需界面「加载已解压」
